# TASK-DB-001 数据库接入与知识库分类表迁移

## 关联需求

- R-001：四类知识库分类及子分类的持久化基础。
- R-010：租户及父子分类隔离。

## 目标与准入

在本项目专属非生产 PostgreSQL 16 建立可重复执行的分类表迁移、最小权限应用连接及租户事务隔离。具体方案见 docs/SCHEMA-知识库分类持久化方案.md、D-017，待确认后执行。

只为本卡申请数据库前置能力的有限准入，不关闭 G-002/G-003/G-004，不修改或连接旧系统数据库，不恢复 Mock/旧测试环境联调，不做邮件、HTTP API 或分类服务编排。

## 输入 / 输出

- 输入：已确认 D-017 表/约束/迁移契约、获准专属 PostgreSQL 16 目标与权限由负责人配置完成的确认；不在聊天中提供凭证。
- 输出：当前项目精确依赖锁、异步连接和租户事务、Alembic 首次分类迁移、真实 PostgreSQL 验证记录。

## 允许修改

- pyproject.toml：依赖声明与项目检查配置。
- requirements.txt：精确版本与哈希。
- src/shared/database.py：受控目标配置、异步引擎、事务租户上下文与安全关闭。
- alembic.ini：无凭证的迁移路径配置。
- scripts/migrations/env.py：迁移入口、目标库/角色核对及事务。
- scripts/migrations/versions/0001_knowledge_categories.py：已确认表、约束、索引、RLS 与非破坏性降级保护。
- tests/shared/test_category_database.py：真实 PostgreSQL 的迁移、权限、事务和隔离测试。

本卡实现/配置文件共 7 个，超过建议的 5 个，原因是依赖锁、标准迁移入口、业务连接及真实数据库验证不可混到一个文件；仍仅一张分类表与共享连接基础，预计不超过 1 天。过程记录允许本卡、SCHEMA 文档、决策、计划、对齐清单和必要验收记录。

## 禁止

- 不读取旧 .env/凭证或使用旧库默认地址，不操作生产，不改旧代码。
- 不执行 DROP/TRUNCATE、破坏性清理或删表 downgrade，不在应用启动时自动迁移。
- 不实现知识库分类服务、上传、解析、检索、邮件或真实 API 联调。
- 未确认方案不得添加依赖或执行迁移；未获准目标库不得试探连接。

## 验收标准

- [ ] 依赖符合 Python 3.13 并精确锁定，连接配置不含明文凭证，目标仅为获准专属非生产 PostgreSQL 16。
- [ ] 首次升级创建 knowledge_categories 与 Alembic 版本记录，重复升级不改动数据；不接管外部已有同名表。
- [ ] 实际表字段、复合主键/父子外键、根键唯一性、空白名称/自环检查和索引符合 D-017。
- [ ] 应用角色非 owner/超级用户/BYPASSRLS，RLS 对读写生效，无租户上下文拒绝，不开放 UPDATE/DELETE。
- [ ] 显式租户过滤及事务内上下文同时存在，连接池复用不串租户；跨租户父子引用拒绝。
- [ ] 失败回滚、提交后新连接可读取均由真实 PostgreSQL 验证，不用 SQLite/Mock 替代。
- [ ] downgrade 不删除表或数据，停写/应用回滚方案已记录。
- [ ] 最小数据库测试、项目测试、ruff、mypy 通过；没有数据库则记录阻断，不跳过用例掩盖。
