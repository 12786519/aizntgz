# TASK-001 实现知识库分类领域模型

## 关联需求

- R-001：支持行业、课程资料、合规、企业文化四类知识库分类及子分类（原始需求第 11 行）。
- R-010：分类对象和分类树按服务端租户上下文隔离。

## 目标

实现 Python 3.13 的纯领域分类对象和分类树处理，不连接数据库、不提供 HTTP API、不调用旧系统、不启动 Mock 或测试服务。

本卡的“创建”指返回新的领域对象，不代表已持久化或已交付可用分类管理界面。真正的存储、请求鉴权及 API 另行决策、拆卡。

## 准入与当前授权

用户在“先准备实施方案，经确认再编码”的下一步建议后回复“开始”，本轮执行任务卡和方案整理。以下 D-016 契约及仅限本卡的准入例外均先供审阅，未确认前不写业务代码。

准入提议：本卡仅处理与 G-002/G-003/G-004 的真实接口、购买权限策略和文件解析无关的分类领域对象；允许这一有限范围先实现，不关闭其他门禁。租户字段为输入的可信上下文值，不模拟完整登录/购买授权。

## 输入 / 输出

- 输入：由后续服务端适配层注入的租户上下文、已有分类对象快照、父分类 ID 与分类名称。
- 输出：四个初始根分类对象、一个新子分类对象、或当前租户的分类树；均为内存值，不保存到数据库。

## 领域契约提案（D-016）

- `TenantContext`：tenant_id（UUID），用于域内隔离；不从模型或请求参数自行生成身份，不宣称此对象完成实际鉴权。
- `KnowledgeCategory`：id、tenant_id、name、parent_id（可空）；不加入尚未确认的状态、排序、数据库字段或课程权限逻辑。
- `CategoryNode`：分类对象及不可变子节点集合；分类对象和树节点均采用 Python 标准库不可变 dataclass。
- `initial_categories(context)`：返回当前租户四类根对象，父 ID 为空、各 ID 不同；仅创建值，不承诺持久化初始化或重复请求幂等。
- `create_child(context, categories, parent_id, name)`：只在当前租户快照内查找父分类，成功返回同租户子对象；父分类缺失与属于其他租户使用相同的不可用错误，不返回外租户详情。
- `build_tree(context, categories)`：先过滤租户再建立索引，按输入顺序组装树；外租户对象不参与关联。当前租户内重复 ID、缺失父节点、自环及多节点环拒绝，防止错挂和循环处理。
- 名称必须非空且不全为空白；本卡不新增重名、最大层级、业务排序、改名、移动、删除和角色策略。输入快照不被修改，不将其他租户对象或名称带入错误结果。
