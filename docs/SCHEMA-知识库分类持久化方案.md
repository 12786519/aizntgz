## 2. 表结构提案

业务表：`knowledge_categories`。

| 字段 | 类型与可空性 | 含义 |
|---|---|---|
| tenant_id | UUID，非空 | 当前分类所属租户，强制隔离键 |
| id | UUID，非空 | 分类 ID，应用生成 |
| parent_id | UUID，可空 | 同租户父分类；根节点为空 |
| root_key | TEXT，可空 | 系统根分类内部键；子分类为空 |
| name | TEXT，非空 | 展示名称，拒绝空字符串和全空白 |
| created_at | TIMESTAMPTZ，非空，数据库当前时间默认值 | 创建时间，按 UTC 语义处理 |

约束与索引：

1. 复合主键 `(tenant_id, id)`，所有查询显式包含 tenant_id。
2. 复合外键 `(tenant_id, parent_id)` → 同表 `(tenant_id, id)`，非延迟校验，删除引用采用 RESTRICT。禁止子分类挂到其他租户；本期不提供删除功能。
3. 根节点必须 parent_id 为空且 root_key 非空，root_key 仅允许 industry/course_material/compliance/culture；子节点必须 parent_id 非空且 root_key 为空。检查条件显式处理 NULL，不能依赖 NULL 表达式自动失败。
4. `(tenant_id, root_key)` 唯一，防止同租户重复初始化同类根；子节点 NULL 键不引入未经确认的同级重名限制。
5. name 去除首尾空白后必须非空；parent_id 不能等于自身 id。
6. 增加 `(tenant_id, parent_id)` 索引支持父子查询。

不新增最大层数、同名限制、改名、移动、删除、软删除、业务排序、课程购买字段或数据库 Tenant 主表。本期只有插入和读取，子分类必须挂在已存在父节点下；无 parent 更新入口。复合外键与自环检查不能独立保证任意多节点无环，读取组树仍做防御性检查，未来增加移动功能需另行设计循环约束。

根键与名称：industry=行业、course_material=课程资料、compliance=合规、culture=企业文化。四类必须在一个事务内幂等初始化，唯一冲突按根键读取既有记录，不覆盖用户数据、不产生重复根 ID；失败全部回滚。

## 3. 租户隔离与事务

```text
后续服务端可信身份
  → tenant_id 上下文（不接受模型/前端覆盖）
  → 当前事务设置 app.current_tenant
  → Repository 显式 tenant_id 过滤
  → PostgreSQL RLS 的 USING / WITH CHECK
  → 同租户复合父子外键
  → 返回分类树
```

- 业务表启用并强制 RLS；读取与写入策略都限定当前事务租户。缺失上下文不返回分类或允许插入，不设置默认租户。
- 每个新事务使用参数化 set_config 设置 app.current_tenant，作用域为当前事务；连接池复用不得继承上一租户。
- 应用角色与迁移所有者分离；应用角色非超级用户、无 BYPASSRLS、非表所有者，仅授予必要 SELECT/INSERT，不授予 UPDATE/DELETE/建表权限。FORCE RLS 不能约束超级用户或 BYPASSRLS，必须检查运行角色。
- 同租户父分类缺失与跨租户父分类使用相同领域错误，不把数据库错误详情/SQL 参数返回调用方。
- 事务提交成功后才报告创建成功；失败回滚，不把 flush 等同于保存成功。数据库异常受控向上报告，禁止静默吞掉。

依据：[PostgreSQL 16 行级安全](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)、[约束与复合外键](https://www.postgresql.org/docs/16/ddl-constraints.html)。

## 4. 数据访问与新增依赖提案

- 使用 SQLAlchemy 2.x 异步访问和 asyncpg 驱动，Alembic 管理迁移；pytest-asyncio 用于事务与数据库集成测试。
- 理由：与 FastAPI 异步基线一致，显式事务、参数化查询和版本迁移可独立验证；不复制旧服务代码或直连旧库。选用的是工具方案，不代表旧项目依赖可以不经锁定直接变成本项目依赖。
- 先记录 D-017、确认后在 TASK-DB-001 统一声明依赖、解析精确版本/哈希并检查 Python 3.13 兼容；不复用暂缓 Mock 的依赖草稿，不在本轮安装。
- 连接配置仅面向经负责人确认的专属非生产库，不输出连接串或凭证，不用猜测的默认地址。不建立真实业务 API、Worker 或 HTTP 测试环境。
- 每个并发任务有独立 AsyncSession；连接超时和事务等待/语句超时需在数据库卡落实，初始值按批准的请求预算与目标库验证，不在缺少目标库时声称已生效。

依据：[SQLAlchemy 异步事务与会话](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html)。

## 5. 迁移、兼容与非破坏性回滚

- 本项新增 knowledge_categories，Alembic 另维护自身版本表；不改现有业务表、消息或外部 API。
- 首次升级创建本表、约束、索引和 RLS；重复升级到同一版本不重复建表或改变数据。发现同名但不受本项目迁移管理的表时停止，不自动接管或 stamp。
- 迁移身份仅在已确认专属开发库执行；业务进程不自行迁移。角色权限、目标库名称和版本先核对，不能连接后才判断是否生产。
- 本项目规则禁止 DROP/TRUNCATE/破坏性删除，因此不实施删表式 downgrade。回滚先停用新写入/入口，再由负责人反向提交应用代码，保留表与数据；迁移降级命令须明确拒绝破坏性操作。修复通过后续向前迁移，不以删除数据恢复。
- 若未来必须物理撤销表/角色或清理测试数据，需单独取得负责人明确处理决定，不属于本次授权；不把物理删除写成自动测试清理步骤。
- 数据库测试只写合成租户数据，事务回滚可用于无持久化案例；必须提交的“重连仍存在”案例保留在专属开发库，不使用 DROP 清场。

## 7. 必须完成的验证

- PostgreSQL 16 的实际升级及重复升级，RLS、约束、索引、角色权限与无上下文拒绝。
- 两个租户的读写隔离、跨租户 parent_id 拒绝，以及连接池从租户 A 切到 B 不串数据。
- 并发初始化仅有四个根；事务中途失败没有半套根或孤立子分类。
- 创建并提交后关闭原连接，在新会话/进程读取仍存在；仅在同一内存列表读取不算通过。
- 空分类、名称空白、无效父关联和树环的受控失败；不新增未批准的同名/层级规则。
- 迁移回滚方案可执行地停用写入并保留数据；测试与文档不得包含 DROP/TRUNCATE。
- 没有可用的获准专属 PostgreSQL 16 时，本数据库卡保持阻断，不用 SQLite、Mock 或 pytest.skip 宣称通过。
