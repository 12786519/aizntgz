# 负责人接入联调操作步骤

> 日期：2026-10-28 ｜ 整理者：Codex ｜ 用途：说明用户、Codex 与旧系统负责人下一步各做什么。

## 1. 先明确当前状态

- 业务范围、文件目标、权限变化和平台学员课程映射已确认，无需重复选择。
- 源码盘点、接口契约草案、接入候选方案已完成；既有隔离测试分批通过，不等于新服务已经实现或真实联调通过。
- 正式身份、测试接口入口、可用邮件 API、实际上游限流/SLA、真实文件样本和端到端幂等证据尚未齐备。
- 推荐路线：先准备一张本地 Mock 联调任务卡，同时收集旧系统测试环境材料；后续逐张任务卡执行。缺失的真实能力继续标记缺口，不用模拟结果替代。

## 2. 第一步：明确谁能管理旧系统

你的动作：确定谁有权管理 `D:/zljy/zljy` 对应系统及其测试环境。如果你本人就是负责人，直接说明；不需要另找一个人签字。若有原开发团队，让其确认一个技术对接人。

需要得到的结果：负责人是谁、是否有独立测试环境、是否允许在该测试环境做身份注册/接口开放/故障测试。源码目录存在不代表有环境操作授权。

Codex 的工作：继续核对本地工程和测试，不操作生产。若需要修改旧系统，先按 AGENTS.md 完成 B0 现状盘点、B1 基线和特征测试、B2 影响分析，再给出具体任务卡、B3 改造策略、B4 安全网与回滚方案。

## 3. 第二步：评审接入方案并准备第一张卡

你的动作：查看 [接入与联调方案](INTEGRATION-接入与联调准备方案.md)第 2–4 节。它们仍是 D-013 候选，不是此前已确认的 D-009 至 D-012。

| 待评审项 | 当前候选内容 |
|---|---|
| 服务身份与认证 | 新服务使用独立注册身份，经旧网关受控访问，不冒用 m6，不拿旧 BFF 私钥 |
| 邮件 | 真实邮件 API 不可用时先 Mock；只向专用测试收件箱或白名单发送 |
| 总时间预算 | 普通外部读取 30 秒、授权解析 10 秒、非流式问答 60 秒、资料下载 15 分钟、邮件受理 10 秒 |

你可以明确接受上述候选，或指出具体修改；接受方案不代表批准生产操作、旧系统未展示的改动或真实 SLA 承诺。

Codex 随后准备一张 M0 本地 Mock 联调任务卡：输入/输出、允许修改文件、禁止事项、验收用例、测试命令、风险及回滚。当前阶段门禁未全关闭，因此需在卡中写明仅限 Mock 的准入范围，先给你审阅；未确认前不直接写业务代码。

这张卡不承担六类真实文件解析、生产接口连接、真实邮件发送或旧系统改造，不把多项未决方案塞进同一实现任务。

## 4. 第三步：收集测试环境最小材料

你或旧系统负责人填写下面的信息即可，不必自行写接口程序。

| 材料 | 要填写的内容 | 如何处理 |
|---|---|---|
| 环境归属 | 本地 / 独立测试服务器；负责人；明确非生产 | 没有环境就填“暂无”，Codex 可先提出隔离环境方案 |
| 可用入口 | 旧网关测试地址、可开放的业务接口、API 文档位置 | 只提供获准的非敏感测试地址和文档，不带 URL 凭证或签名参数 |
| 新服务身份 | 注册名称、允许能力、受众、是否已加入白名单 | 名称由负责人正式注册；rag-knowledge 目前只是候选名 |
| 凭证配置状态 | 是否已由负责人通过获准方式完成测试环境配置 | 不粘贴密钥、令牌、.env、数据库连接串；不让 Codex读取它们 |
| 认证与撤销 | 凭证由谁签发、谁验证、如何撤销/轮换、是否支持用户委托 | 可提供脱敏流程说明，技术细节由 Codex 辅助核对 |
| 邮件 | 可用 API/文档；专用测试收件箱或白名单的配置状态 | 没有接口就填“暂无”；不把站内信当作邮件服务 |
| 限流 | 各类调用配额、并发限制、429 是否返回 Retry-After | 不知道就填“待测/待确认”，不要把源码默认值当实际部署值 |
| SLA / 测试窗口 | 支持时间、故障联系人、可用性计量、允许故障注入的时间和范围 | 无承诺就明确“未承诺”；只在获准范围做故障测试 |

完成标准：上表有负责人和状态，缺项明确；材料不足时可继续 Mock，不能自动升级为真实联调。

## 5. 第四步：准备测试账号和真实文件

你的动作：让环境负责人在测试系统准备合成账号/租户，不使用真实学员与订单数据。

- 至少两个互相隔离的测试租户。
- 学员场景覆盖有效购买、未购买、已过期、已退款、协议未完成。
- 后台账号至少覆盖有对应权限和无对应权限两类。
- 至少两门不同权限范围的课程及对应知识库；账号、课程和知识库关联由测试系统负责人配置。
- 账号密码和登录令牌不发到聊天；先提供已配置的场景清单，后续认证方式在实施卡中明确。

内容方提供六类各至少 10 份脱敏真实样本；表格至少 5 份 XLS + 5 份 XLSX，幻灯片至少 5 份 PPT + 5 份 PPTX。给出获准本地目录及使用授权。按 D-010 标注预期文字、问题答案及页码/视频时间段；无可用样本就继续保留质量验收缺口。

完成标准：知道每个测试身份可以访问什么、不可以访问什么；每份样本有预期结果。自动生成文件只补边界测试，不冒充真实样本。

## 6. 第五步：完成本地 Mock 联调

你的动作：审阅并确认第二步产出的单张任务卡和实施计划。此后不必逐条批准卡内可逆操作。

Codex 的工作：在获准文件范围内按 TDD 实现模拟接口及新项目适配，验证成功、权限拒绝、超时、429、重复请求、无效响应和请求预算。真实外部接口仍不连接。

交付应包含：代码、自动化测试、实际执行结果、差异检查、任务卡状态、可回滚提交。按任务范围执行项目要求的 pytest、ruff、mypy；不能运行的检查必须说明原因和替代验证。

完成标准：这张卡的验收通过，且明确标记 Mock 验证层级。它不自动关闭真实接口、邮件或 SLA 的证据缺口。

## 7. 第六步：注册身份并逐接口真实联调

你的动作：由环境负责人确认第三步的测试材料与授权范围，人工配置凭证；若旧系统改造是必须项，先走完 B0–B2 和对应任务卡。若没有修改旧系统，仅使用已有开放能力，则按确认契约接入。

Codex 的工作：一张任务卡只处理一个可验收闭环，例如先验证课程资料读取与有效权益校验；完成后再处理审计、同步回写、邮件等。保持服务端身份、租户、课程和知识库过滤，不直接连接旧业务数据库。

每个接口至少验证：正确身份成功、无效身份拒绝、越权拒绝、超时有界、错误可追踪。邮件需核实实际受理、状态对账和测试收件箱结果，不能只看 HTTP 成功。

完成标准：真实调用有脱敏证据和 trace/request 关联；已经开通的接口与仍为 Mock 的接口清楚列出。未取得实际入口或身份时停止该接口的真实接入，不猜测或冒名。

## 8. 第七步：故障、重复、权限和容量验收

你的动作：确认故障测试仅在独立测试环境进行，并由环境负责人明确允许的重启/断连/重放范围；提供邮件测试白名单和样本。不要在生产系统演练。

Codex 执行并留证：

- 同一请求顺序重复、并发重复、同键不同参数、跨租户相同业务键。
- 已提交但响应丢失、消息消费后确认前重启、失败回写重复、审计并发去重、邮件超时后对账。
- 退款、到期、撤权之后，重新问答、缓存命中、引用打开和流式后续输出均不越权。
- 开通 60 秒、撤权 30 秒目标；文件识别、视频语音/画面检索和引用质量按各自任务验收。
- 获准负载下的响应时间、超时率、429 与并发；实测容量和上游承诺分别记录，短期压测不宣称已证明整月 99.9%。

完成标准：业务副作用计数符合预期，无重复逻辑入库/错误撤权/重复发送，权限与质量门槛满足；失败项先修复再复测，不以修改测试来隐藏问题。

## 9. 第八步：关闭门禁并进入业务实现

Codex 把证据回填对齐清单、契约、决策、计划和验收资料；你审查完成项和仍缺项目。

- G-002：接口契约、身份、真实开放入口、故障/幂等及限流/SLA 证据满足准入；邮件若仍缺失，只能在负责人书面同意的对应范围内保留 Mock，不自动削减首期要求。
- G-003：授权映射已确认，部分退款和权限时限的实际符合性完成验证。
- G-004：六类真实样本、资源限制、处理方案及要求的验证证据齐备。正式质量验收仍按后续解析任务执行，不能用 Mock 或旧单测代替。

条件不足就保留具体阻断；条件满足后复核首张业务任务卡、独立分支和实施计划，按项目逐任务闭环推进。合并和上线仍由负责人执行。

## 10. 你现在可以直接回复的内容

先提供最少三项：

1. 你是否就是旧系统负责人；如果不是，谁能负责测试环境接入。
2. 是否已有独立测试环境；有则提供不带凭证的获准测试入口或文档位置，无则明确“暂无”。
3. 是否接受 D-013 接入与总预算候选，并要求 Codex 先准备本地 Mock 联调任务卡及准入说明，暂不修改旧系统或连接生产。

这三项之后，Codex 可先把第一张可审阅任务卡做出来；真实样本、邮件和 SLA 材料可由对应负责人另外准备，不必等全部齐备才整理 Mock 实施方案。
