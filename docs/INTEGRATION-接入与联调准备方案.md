## 2. 身份与认证拓扑候选方案

建议逻辑服务名 `rag-knowledge`，为**候选名，未注册**。请求处理、入库 Worker、审计发送、邮件调用分别配置最小能力；是否拆为多个主体 ID 由旧网关的注册能力决定，本文不假设已有账户或 scope。

```text
用户
  → 既有身份入口验证用户凭证
  → 旧网关：核实主体 + 服务身份 + 本次允许能力
      → 新 RAG 服务（保留 requester tenant/user，限定业务工具）
          → 受控旧网关工具入口（能力、调用方、请求绑定校验）
              → 换发旧 M1/M2/M3 等目标域受限令牌
              → 业务域再次校验身份、scope、本人资源及租户

可信后台任务来源
  → 已注册 Worker 身份 + 服务端持久化任务租户/来源
  → 获准资料同步 API（不经模型选择租户或地址）

上述调用链
  → request_id + trace_id + 稳定业务事件 ID
  → 独立最小权限审计发送身份 → 旧审计 API
```

- 用户凭证验签后才形成身份；模型只提出允许的业务参数。服务身份不能替代学员购买权益，课程访问遵守已确认 D-012。
- 现有旧 BFF `/internal/agent-tools/{capability}` 只接受 m6，且仅在旧客服路由签发对应委托；新服务新增的 caller、入口签发与能力清单必须显式配置，不能仅修改 caller 名字绕过校验。
- 优先沿用旧网关受控签发和目标域换签，不将旧 BFF 私钥下发新服务。新服务的身份认证方法和凭证分发由负责人按现有体系确认，不在此擅选 mTLS/OAuth 等新依赖。
- 用户委托的角色、能力、aud、kid、有效期与 request_id 均须校验；后台任务使用专用身份，不把学员短期委托当作永久 Worker 凭证。
- 旧默认内部令牌和委托有效期均为 300 秒；这是代码默认值，不代表新项目必须接受 300 秒授权缓存，也不替代 D-009 的实时撤权。
- 失效、角色变化或撤销注册后，后续请求不得继续放行。私钥轮换、kid 切换与旧凭证过渡需负责人提供测试方案，当前不读取真实密钥验证。

证据：[旧委托白名单及换签](D:/zljy/zljy/services/gateway/api_bff/app/agent_tools.py:53)、[旧签发路由限制](D:/zljy/zljy/services/gateway/api_bff/app/delegation.py:20)、[有效期默认配置](D:/zljy/zljy/services/gateway/api_bff/app/config.py:43)。

## 3. MAIL01 逻辑契约草案

下面是待邮件服务负责人映射的业务要求，**未指定 HTTP 路径、实际字段或已存在服务**。具体接口批准前只能用于后续 Mock 设计。

| 方向 | 建议语义 | 校验 / 幂等要求 |
|---|---|---|
| 请求身份 | 可信服务调用者 + 用户授权上下文 | tenant/user/收件人均由服务端确定，模型无权指定实际邮箱 |
| 请求业务 | 模板引用、业务对象引用、服务端收件人引用、受控模板参数、可选附件引用、稳定业务发送键、trace/request 关联 | 附件须已生成且属当前授权范围；不接受模型生成的任意 URL、模板或原始文件路径 |
| 受理结果 | 稳定发送任务引用、状态、是否重复受理 | 相同发送键和相同语义只受理一次；相同键不同内容应拒绝，错误码由真实契约确定 |
| 状态查询 / 回执 | 已受理、处理中、成功、失败、需要人工处理等可核验状态 | 受理成功不等于已投递；若上游不提供状态或无法去重，响应丢失时禁止自动重发 |
| 重试 | 仅对已确认去重的发送请求进行有界重试；无权限/模板/收件人错误不重试 | 按同一稳定业务发送键对账；不能以每次重试生成新键绕过重复保护 |

真实发送联调只允许测试收件箱或获准白名单，不向真实学员发送。没有旧邮件 API 时保留 Mock，不用新项目 SMTP 直发替代既有服务。

## 4. 总请求预算与限流 / SLA

以下为 D-011 的**补充候选值，待评审和实现**。已有 D-011 的 3 秒连接、10 秒读取、最多 3 次尝试保持；新总预算可提前终止，不保证耗尽全部尝试。

| 操作 | 建议总预算 | 包含与中止规则 |
|---|---|---|
| 单次普通只读外部操作 | 30 秒 | 包含排队、连接、读取、重试等待与抖动；全部尝试共用同一绝对截止时间；剩余不足时不再发起尝试 |
| 授权解析阶段 | 10 秒 | 所需权限/机构查询共享阶段预算；无法形成可靠授权即拒绝受限检索，不带旧授权兜底 |
| 新项目普通非流式问答 | 60 秒 | 授权、召回、生成及发送前复核共享根截止时间；子调用预算取自身上限与根剩余时间的较小值；超时结束请求 |
| 资料下载单任务 | 15 分钟 | 读取空闲超时 90 秒，总下载/校验受任务截止时间、已确认文件大小限制共同约束；入库异步处理，不等待同步问答完成 |
| 邮件受理 | 10 秒 | 仅受理动作预算；真实投递 SLA 另议，结果不明确时按稳定发送键查询对账，不自动另发 |

同步客户端取消/根请求超时后取消子任务，避免用户已放弃而后台仍重试；重试等待与 Retry-After 不得超出剩余预算。流式最大持续时间、首字时限、大模型阶段预算及队列租约需按任务另行评审，不以“60 秒问答”推断已批准这些值。

已核对旧 BFF 默认 upstream_timeout_seconds=60.0、trade_rate_limit_enabled=False，现有规则覆盖部分交易、匿名认证与公开目录入口。这不证明部署环境关闭限流，也不证明旧 RAG 查询已具备每用户 60/每租户 600 次的限额。真实上游限额与 D-011 新项目初始评估值分开记录。

可用性计量候选：按月统计已通过认证、参数有效的知识查询中，因服务故障未能完成的请求；业务权限拒绝与合法“无答案”不记作服务故障。用户取消、429、上游故障及维护窗口如何归类需双方书面明确，不能靠排除失败来宣称达到 99.9%。压测可验证容量与延迟，短期测试不能证明整月 SLA。

证据：[旧网关超时和开关](D:/zljy/zljy/services/gateway/api_bff/app/config.py:43)、[现有限流路由规则](D:/zljy/zljy/services/gateway/api_bff/app/trade_rate_limit.py:110)。

## 5. 联调环境与端到端幂等验收

| 层次 | 准备与执行 | 能证明什么 / 当前状态 |
|---|---|---|
| L0 已有隔离单测 | 使用源码中的替身与 MockTransport；禁用外部服务连接 | 部分签名、上下文、响应解包与重复请求分支；本次 20 passed，见第 6 节 |
| L1 新服务 Mock 联调 | 先建独立任务卡，获准后按草案构建新服务到模拟上游链路；仅合成租户/用户，无生产凭证 | 能证明新适配器和授权编排，不能代表旧服务真实契约、邮件或数据库行为；当前未实现 |
| L2 获准旧系统测试环境 | 环境所有者确认非生产地址、主体、测试数据与范围；人工在获准环境配置凭证；Codex 不读取/打印凭证或 .env | 执行真实 HTTP、数据库/队列与专用测试邮件链路；当前无可核实接入条件 |

真实幂等验收矩阵：

| 场景 | 必须核对的业务结果 |
|---|---|
| 相同资料上传顺序重复 / 并发重复 | 同一逻辑文件版本和索引副作用不重复；同时验证不同内容不被误去重 |
| 事务提交后、HTTP 响应前断开 | 重试取得同一业务结果，不重复创建版本、发送邮件或追加相同审计事件 |
| Outbox 发布后消费者确认前重启 | 重放仍只产生一次逻辑入库效果；消息被消费不等于业务事务已提交 |
| 失败回写重复 / 响应丢失 | 明确 retry_count 和 next_retry_at 语义；现有会重复计数的行为须作为缺口，不以 event_id 存在宣称幂等 |
| 审计并发重复 | 同租户同 source_event_id 在实际事务锁及提交条件下只追加一次；不能用 Session 替身证明数据库竞争安全 |
| 邮件受理后超时 / 重复回执 | 一次逻辑发送、相同发送引用，状态可对账；没有下游去重能力就不能承诺端到端一次发送 |
| 同键不同参数 / 跨租户同键 | 参数冲突不得复用错误结果；幂等键作用域包含可信租户和操作类型，互不影响 |

每条真实验证记录测试运行 ID、源码版本、环境标识、租户别名、trace/request、业务键摘要、注入故障点、前后副作用计数与预期结果。证据不保存原始凭证、真实客户资料或收件人地址。未验证项保持未通过，不能用“所有单测通过”替代。
