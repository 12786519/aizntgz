## 2. 歧义与缺失

| 项目 | 可选解释 | 影响 |
|---|---|---|
| 知识库可见范围 | 全租户共享 / 按角色 / 按机构、课程、文档授权 | 数据模型与检索过滤逻辑 |
| MP4 检索 | 仅字幕 / ASR 转写 / 视频画面 OCR 也纳入 | 成本、解析流程、检索质量 |
| 六类文件标准 | 已确认：PDF、XLS、PPT、DOCX、图片、MP4 全部首期支持 | M1 须完成六类格式样本验证和验收 |
| 购买与有效期 | 课程级 / 资料级 / 订单状态驱动 | 防越权规则和缓存失效机制 |
| 学习计划 | 规则推荐 / 大模型生成 / 结合学习行为数据 | 是否依赖旧系统学习进度数据 |
| 报表统计口径 | 实时查询 / T+1 汇总 / 定时生成 | 数据库设计、性能与结果一致性 |
| 客服转人工 | 固定关键词 / 置信度阈值 / 用户主动触发 | 人工坐席接口与服务 SLA |
| 邮件发送 | 用户指定地址 / 仅绑定邮箱 / 报表定时发送 | 权限、合规与邮件服务契约 |

## 3. 隐含需求

以下内容为上线必需，但需求文档未完整定义，均为推测：

- 服务端必须强制传递租户、用户和授权课程范围，不能信任前端或模型传入的身份参数。
- 入库、同步与邮件发送需要幂等键、失败重试、死信处理和人工重放机制。
- 资料更新应先完成新版本入库与校验，再原子切换，避免检索空窗。
- 需要检索效果评测集及准确率、引用正确率等验收标准。
- 需要数据库迁移、备份恢复、监控告警、灰度和回滚方案。
- 需要防提示词注入、模型输出安全控制及敏感数据脱敏策略。

## 4. 领域模型

以下为推测的领域模型：

Tenant → User、Role、Permission；Tenant → KnowledgeCategory → Document → DocumentChunk。课程资料关联 course_id、source_ref_id 与 version；IngestionTask 记录入库阶段；SyncEvent 和 OutboxEvent 负责可靠同步；RetrievalLog 与 AgentLog 使用 trace_id 关联审计。Course、Order、LearningProgress、Email、AuditLog 由已有系统 API 提供。

## 5. 外部依赖与集成点

- 已有课程、订单、支付、代理分销、用户权限、邮件和审计服务通过 API 复用。来源：需求文档:7。
- 以下具体接口职责均为推测：课程资料与有效期、订单退款和支付状态、角色范围、机构经营数据、邮件发送、审计留痕。
- OCR/ASR、Embedding 与大模型服务的具体供应商和 SLA 均为推测，尚未确认。

## 6. 风险清单

以下风险与缓解方案均为推测：

| 类别 | 风险 | 缓解方案 |
|---|---|---|
| 技术 | 六类格式和 OCR/ASR 的解析质量不达标 | 先以真实样本进行技术验证，按格式分别设验收标准 |
| 技术 | 旧系统回调重复或丢失 | event_id 去重、Outbox、轮询和每日对账 |
| 技术 | 检索越权 | 鉴权在检索前执行，SQL 层强制租户与课程过滤 |
| 数据 | 旧系统资料更新导致新旧版本混乱 | 候选新版本成功后才原子切换 |
| 数据 | 报表口径与旧系统不一致 | 先签署指标定义，建立抽样对账用例 |
| 进度 | 外部接口文档或联调环境迟到 | 将 OpenAPI、Mock 和 SLA 设为 M0 准入条件 |
| 进度 | 智能体范围膨胀 | 先锁定三个智能体与独立客服边界，P1 功能分期 |

## 7. MVP 范围建议

以下范围建议均为推测：

| 范围 | 内容 | 理由 |
|---|---|---|
| 必须做 | 六类文件入库、任务状态与重试、租户/购买/有效期鉴权、带引用检索、学习助手基础答疑、审计和监控 | 组成安全可验证的 RAG 最小闭环，且符合已确认的首期范围 |
| 应该做 | 课程资料同步、版本切换、订单/课程/进度授权查询、基础客服 FAQ | 直接支撑现有业务和资料新鲜度 |
| 可以做 | 报表邮件、机构统计图表、导出 | 价值明确，但依赖数据口径或外部服务确认 |
| 不做 | 未经确认的自动出题、错题本、定时报表、视频画面理解、复杂人工客服坐席系统 | 原始需求未定义完整规则、验收标准或外部接口 |
